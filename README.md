# novel-dissector

把一本本地 txt 长篇小说拆成**结构化数据 + 交互可视化报告**，并产出**续写资产包**。

> 纯 Python 标准库 + 手写 SVG。零第三方依赖、无 CDN、断网可用。

---

## 它解决什么

你有一本小说，想知道：
- 节奏到底怎么走的？哪里注水？哪里是高潮？
- 人物关系网长什么样？谁跟谁常同框？
- 作者的语言习惯是什么？标题怎么起？章末怎么断？
- **如果要续写，第一章该怎么写才像原作？**

`novel-dissector` 把这些问题变成可量化的表格和图表。

## 18 个维度

| 尺度 | 维度 |
|---|---|
| 全书 | 元数据 · 结构 · 词汇 · 世界观 · 文体 |
| 章间 | 人物 · 关系网 · 剧情分卷 · 灌水/高潮 · 转折点 |
| 章 | 章末钩子形态 · 开场方式 · 伏笔时间线 |
| 章内 | 节奏模板 · 对话轮次 · 爽文桥段 |
| 句段 | 语言指纹 · 心声机制 · 台词音色 · 场景迁移 |

## 8 个可视化页面

`可视化总览` · `情感曲线` · `人物关系网` · `灌水高潮热力图` · `语言指纹` · `转折点分析` · `叙事工程学` · `章内工程学`

## ★ 续写资产（最有价值的部分）

| 资产 | 说明 |
|---|---|
| **结局判定** | 失败/胜利/开放/轮回 —— 搞错这个续写全歪 |
| 未回收伏笔 | 按"结局前消失章数"排序，天然续写接口 |
| 角色终局状态 | 末现章 + 最后出现的上下文原文 |
| 续写硬约束 | 字数安全区、对话回合/章、心声/章、段均汉字… |
| **绝对禁忌** | 例："不可让心声回归""不可写战斗+感情双高峰" |

## 实测案例

《这个人明明很强却偏要坑萝莉师傅》（132.6 万字 / 589 章 / 已完结）

拆出的核心结论：
- **第 501 章是全书硬转折**：心声 −67%、甜度 −68%、战斗 +89%，三个开关同时按下
- **心声 vs 灌水率 r = −0.844 强负相关**：喜剧机制退场与节奏塌陷完全同步
- **反转 2837 次 vs 打脸 173 次**：这本书靠"转折"驱动，不是靠"打脸"
- **589 章无一章零对话**，章均 22.8 回合，节奏高度模板化
- **结局是失败/牺牲**，林恩败给轮回，非胜利收尾

产出规模：8 个交互页 · 43 份数据 · 34 个脚本，终检 **ALL PASS**。

## 设计原则

1. **先探测再动手** —— 数据撑不住的维度直接放弃并写明原因
2. **结论要交叉验证** —— 转折点需在 3 个独立维度同时出现才下结论
3. **数字要对得上** —— 交付前跑终检，ALL PASS 才算完
4. **不臆测语义** —— 只报统计能支撑的，不确定的标"推断"
5. **续写资产必须含结局判定** —— 否则不算完成

## 环境要求

- Python 3.9+ （仅标准库：`re` `json` `collections` `math` `statistics` `csv`）
- Node （可选，用于校验生成页面的 JS 语法）

**不需要**：jieba / matplotlib / networkx / 任何 pip 包。

## 已知坑（写在 SKILL.md 里，这里再提醒）

1. **角色抽取被副词污染**：`X说：「` 会捕到"认真说""微笑道"。用白名单锚定。
2. **路径含 `&` 或中文时 `write` 会静默失败**：用 Node 以 UTF-8 Buffer 写文件，写完 `ls` 确认。
3. **JS 模板字符串里的反引号**会截断 HTML：改用 `.replace()` 占位符替换。
